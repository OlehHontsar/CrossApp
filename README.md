# CrossApp 
Наскрізний проєкт з крос-платформного програмування. 
Предметна область: Замовлення. Сутності: Customer, Product, Order, OrderLine. 
Призначення: оформлення замовлень і підрахунок сум. 

## Запуск та Управління Проєктом
```bash
# Збірка всього рішення
dotnet build 

# Локальний запуск консольного інтерфейсу з завантаженням файлу за замовчуванням
dotnet run --project src/Cli 

# Запуск консольного інтерфейсу з передачею іншого файлу через аргументи
dotnet run --project src/Cli data/sample.csv
```

## Середовище Розробки 
.NET SDK 10.0, Windows 11 x64

## Лабораторна робота 2 & 3: Архітектурне розділення та Відмовостійкий Імпорт

### Структура проєкту та конвенція каталогів `Core`
Для забезпечення чистої архітектури за принципом SoC (Separation of Concerns) уся системна та доменна логіка винесена у бібліотеку класів (`Core`). Проєкт `Cli` виступає виключно інфраструктурним представленням (UI).

Згідно з домовленістю на семестр, у проєкті `Core` розгорнуто таку структуру каталогів для нашої предметної області:
* `Core/Dto/` — record-типи формату даних (тиждень 3): `CustomerDto`, `ProductDto`, `OrderDto`, `OrderLineDto`
* `Core/Domain/` — сутності з поведінкою та інваріантами (тиждень 4): `Customer`, `Product`, `Order`, `OrderLine`
* `Core/Storage/` — реалізації сховищ даних (тиждень 5)
* `Core/Import/` — логіка відмовостійкого зчитування файлів

*Примітка: для збереження порожніх папок у Git до них додано файли-заглушки `.gitkeep`.*

### Результати порівняння режимів публікації (Лаб 2)

Збірка та вимірювання розмірів вихідних папок здійснювалися на ОС **Windows 11 x64** за допомогою команд:
* `dotnet publish src/Cli -c Release -r win-x64 --self-contained true`
* `dotnet publish src/Cli -c Release -r win-x64 --self-contained true -p:PublishTrimmed=true`
* `dotnet publish src/Cli -c Release -r win-x64 --self-contained false`

| RID | Режим публікації / Параметри | Розмір publish | Потрібен runtime | Особливості розгортання |
| :--- | :--- | :--- | :--- | :--- |
| **win-x64** | `self-contained true` | **76.68 МБ** | ні | Повна автономність, ~200+ системних файлів у папці. |
| **win-x64** | `self-contained` + `PublishTrimmed=true` | **12.35 МБ** | ні | Оптимізовано. Статичний лінкер вирізав ~64 МБ мертвого коду .NET. |
| **win-x64** | `framework-dependent` (`false`) | **0.19 МБ** | так (.NET 10) | Мінімальна вага бінарника, але вимагає встановленого SDK у клієнта. |

### Самоперевірка та Стійкість Імпорту (Лаб 3)
Для перевірки стійкості додатка у файл `data/sample.csv` було внесено 3 дефектні рядки. Застосунок успішно локалізував помилки, вивів номери рядків у термінал, не перериваючи імпорт решти 10 цілісних записів:
* **Рядок 12:** Відсутня 5-та колонка кількості товарів (спрацював патерн властивості `{ Length: < 5 }`).
* **Рядок 13:** Текстове значення кількості `"багато"` (спрацював патерн списку з фільтром `when !int.TryParse`).
* **Рядок 14:** Порожній обов'язковий артикул товарної позиції (спрацював логічний патерн `or`).
